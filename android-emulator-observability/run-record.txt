Suite failure root cause (verified in source + live surfaces)
-------------------------------------------------------------
exercise_saved_profile_management (android_smoke_impl.py:3827) opens the saved
servers sheet via tap_action(device, "daily_profile_management_open",
("Saved servers",)) — i.e. it taps a node whose text/content-desc is exactly
'Saved servers'.

On ed43536 the connected workspaces header's server target carried
accessibilityLabel='Saved servers' (it opened the servers sheet directly).
The unified-switcher refactor replaced that target with
'Switch server and session, {srv}, {sess}' and absorbed the saved-servers
entry point into the switcher sheet's 'Manage servers' action.

On 21f8b28's connected workspaces surface there is NO node matching
'Saved servers':
- serverRow: switcher target + ConnectionStatus + 'Server connection' menu only
- 'Saved servers' exists only as (a) the a11y label of the 'Manage servers'
  button inside savedHome — rendered only when !attempted (disconnected home),
  and (b) the NativeSheet title once the sheet is already open — unreachable
  without first opening the sheet via 'Manage servers' inside the switcher or
  the disconnected home.
=> Deterministic ui_timeout; the daily-profile flow (edit/switch/delete) and
   every subsequent stage can never start. Not a flake.

Fix options for the candidate: expose a 'Saved servers' (or suite-known)
affordance on the connected workspaces surface — e.g. restore a labeled row,
or add a 'Saved servers' entry to the server menu sheet — or update the driver
to navigate switcher -> 'Manage servers'.
