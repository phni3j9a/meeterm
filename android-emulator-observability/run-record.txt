FAILURE ANALYSIS (verified three ways)
--------------------------------------
Stage: daily_profile_switch_second_boundary / session_switcher_timeout

The updated driver flow (android_smoke_impl.py:3764+): in the Saved servers
sheet, tap the connected-surface "other" saved profile → the app is designed to
expand that profile inside the unified session switcher → wait for switcher
rows labeled "tmux session {sess} on {profile} ({user}@{host}:{port})" → select
explicitly → Connected + workspace row.

App-side mechanism (App.tsx:3222-3231): the connected profile tap sets
  switcherProfileAfterServerSheetRef.current = profile; setSheet(null);
and NativeSheet's onDismiss handler (App.tsx:3644-3660) then consumes the ref
and calls openSessionSwitcher(target).

ROOT CAUSE — NativeSheet is an RN <Modal> (App.tsx:748) whose dismiss logic is
wired ONLY through the Modal `onDismiss` prop. react-native's own source says:
  node_modules/react-native/Libraries/Modal/Modal.js:318-320
  "OnDismiss is implemented on iOS only."
On Android the callback never fires, so the ref is never consumed and
openSessionSwitcher is never invoked — the sheet simply closes to the plain
workspaces list. DETERMINISTIC (not a flake, not a timing race).

Failure evidence:
- ssh-failure-state.txt at timeout: connection_state=ready, workspace_row=yes,
  saved_servers_sheet=no, runtime_picker=no — sheet closed, no switcher.
- ssh-terminal-failure.png: clean workspaces list (Android daily fixture ·
  meeterm + Connected), no sheet/dialog.
- LIVE REPRO (same build, manual drive): Workspaces → Server connection →
  "Switch session" menu row (the sibling deferred branch,
  openSwitcherAfterServerMenuRef — same mechanism) → sheet closes → plain
  workspaces, NO session switcher. Byte-identical dead-end.

Sibling latent breaks — the same iOS-only onDismiss dispatch is used for every
deferred post-sheet action, so all of these are dead on Android:
  * openSwitcherAfterServerMenuRef     (menu "Switch session" row)
  * switcherProfileAfterServerSheetRef (connected saved-profile tap — the suite path)
  * reopenSwitcherAfterManageRef       (reopen switcher after manage-servers)
The mechanism has existed since 8233a2e (initial unified switcher) and was
latent on Android — earlier suite stages never drove these surfaces (items 1–5
were verified through the header `open-session-switcher` target, which calls
openSessionSwitcher() directly and is UNAFFECTED).

Fix direction: dispatch deferred actions where the sheet actually closes —
e.g. call openSessionSwitcher(profile) directly after setSheet(null) at the
connectSavedProfile call-site (pending-modal ordering), or move dispatch to a
useEffect keyed on `sheet` transition / into a shared closeSheet() wrapper or
Modal onRequestClose — anything but Modal.onDismiss.
