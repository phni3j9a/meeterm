# 第5版の情報設計とAppllama調査

確認日: 2026-09-07

## 今回の問い

ユーザーの「前回の続きは不要」「3タブ構成にこだわらず、このアプリに最適なUI/UXを」という要望を起点に、画面を減らすだけでなく、サーバー・ワークスペース・設定の関係を見直した。

製品の中心はサーバー上のtmux windowを選んでpaneで作業すること。サーバーは一覧の範囲、ワークスペースは日常の選択対象、設定は補助機能であり、同列の3タブとして扱う必然性は弱い。paneをタブとして扱う製品の意味は維持する。

## 比較した構造

| 案 | 評価 |
| --- | --- |
| ワークスペース・サーバー・設定の3タブ | 各入口は見つけやすいが、上下関係と頻度の異なる機能が同列になり、一覧の面積を使う |
| サーバー一覧を最上位にする階層 | 初回や複数サーバーの識別には明快。ただし通常のワークスペースへ一段余計に進む |
| ワークスペースを主画面、サーバーを選択シート、設定を補助画面 | 採用。普段の作業を直接選べ、接続先と表示調整は必要なときに呼び出せる |

複数サーバーを混在させた統合一覧、常設サイドバー、ファイル管理などは追加しない。対象サーバーを明示した一つの作業一覧を主面にする。

## 調査範囲

AppllamaでTermius、Bear、Working Copyを検索した。Working Copyは候補がなかった。Termiusのother-tabs全19画面、Bearのother-tabs全15画面を取得し、接続先の管理、作業一覧、編集、設定の境界を確認した。

加えて「library」のキーワード検索と「minimal project library toolbar settings navigation」の意味検索をそれぞれ3ページ確認した。今回の重複除外後の静止画90枚をダウンロードし、12枚のコンタクトシートで実見した。過去に確認した画像の再参照を含むため、前版までの数へ加算していない。作業用画像とメタデータは `/tmp/meeterm-r5/references/` に保存。動画は今回の参考アプリ調査では使用していない。

検索候補には読書・音楽・学習アプリのライブラリも含まれた。それらの推薦カード、最近の作業枠、課金導線、広い機能向けのタブ構成はmeetermへ採用していない。

## 採用する操作原則

- ホームは「前回の続き」と「ほかの作業」に分けず、全件を一つの一覧へ。現在のworkspaceも同じ行構造で表示する。
- ブランド、キャラクター、接続先、一覧という順で構成し、下部3タブは撤去する。余った面積を埋めるための別のカードや常設バーは加えない。
- workspaceを開くとターミナルへ進む。戻ると同じ一覧位置、検索からなら検索語と結果位置へ戻る。
- ターミナルのworkspace選択はその場で置き換え、過去のworkspaceを戻る履歴に積まない。
- 設定には開いた起点を持たせる。調整後に元の作業へ戻り、入力やpane状態を保つ。
- サーバーの選択は確認が完了してから確定する。未確認ホストを選んでキャンセルしても、元サーバーと作業場所を維持する。
- 再接続は押した画面で進める。ホームから意図せずターミナルへ飛ばない。
- 接続済みの空一覧と、未接続でまだ作業を取得していない状態を区別する。

変更対象は操作できるHTMLモック。tmuxの意味、React Native/Rust/nativeの実装境界、ネイティブ製品の検証要件を変更するものではない。
