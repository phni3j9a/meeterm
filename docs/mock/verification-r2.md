# HTML mock 検証記録

確認日: 2026-09-07 / 改訂版02

この文書は第2版の実施記録。`previews/` は現在第3版へ更新済みで、第2版の主要画面は `previews/before-r2/` に保存している。

## 環境と範囲

Ubuntu上のChromiumをPuppeteerで起動し、HTMLモックを検証した。組み込みBrowserは `Importing module "node:process" is not allowed in node_repl` で起動できなかったため、独立したローカルブラウザを使用した。

対象は `docs/mock/index.html`。実際のSSH、tmux、Android、iOS、ネイティブGPU、OSの日本語IMEは検証対象外。画面内のCLI出力・テスト成功ログは固定サンプルであり、この検証の結果ではない。製品本体・ネイティブ依存関係・CIは変更していない。

## 改善ループ

Appllamaで実際に見た静止画は計49枚。Termius・Bear・Notionに加え、改訂時にBearの設定とCraftのライブラリ／ホームを調査した。接続済みTermiusのターミナル画面や動画を見たという主張ではない。出典は [research.md](./research.md) に記載。

Astra Highによる実装と独立した視覚批評、別担当の機能レビュー、主担当の実ブラウザ確認を組み合わせた。初回改訂後も、画像と実操作で発見した問題を修正して再確認した。

- 文字階層と余白を再設計。行タイトル17px、補助情報13px、ターミナル既定14px、HTMLの入力欄は16px以上。
- 再開カードを縮め、選択中のワークスペースを一覧へ重複表示しない構成に変更。
- 主要操作部品の幅と高さを44px以上に調整。狭幅の特殊キーは横スクロールと続きの手掛かりを用意。
- Ctrl、タブ切り替えなどで画面全体がフェードする挙動を廃止。
- キーボード表示中の初訪ペインで入力欄を見せ、既訪ペインのスクロール位置は保持。
- 長い名前の選択タブが画面外へ戻る問題を修正。長い接続先名は省略し、接続状態を単一行で表示。
- シートの戻る履歴と初期フォーカスを修正。フォームエラーを該当項目の直下に表示。
- 空の状態、接続失敗など8状態を直接選べるプレビューを追加。
- 空の状態に生成した挿絵を配置。日本語を含むM PLUS 1 CodeとともにHTML内へ埋め込み。

## レイアウトと視覚確認

6サイズ × 2テーマ × 4画面の計48パターンで、ドキュメントの横方向のはみ出しがないことを確認した。

| 幅 × 高さ（CSS px） | 用途 |
| --- | --- |
| 320 × 640 | 小さいスマートフォン |
| 390 × 844 | 標準のスマートフォン |
| 600 × 800 | 幅の広いモバイル表示 |
| 844 × 390 | 横向き |
| 1024 × 768 | 小さいPC画面 |
| 1440 × 1050 | PCでのレビュー表示 |

さらに320/390px幅 × 2テーマ × 8状態の32パターンを撮影し、横方向のはみ出しを寸法確認した。全80パターンを1枚ずつ目視したという意味ではない。主要画面の両テーマ、空の状態、接続エラー、確認シート、キーボード、長い名前、狭幅・横向き・デスクトップを実際の画像で確認した。

主要画面・サーバー追加・引き継ぎの表示中に、QWERTYサンプルキーボードを除く可視操作部品の44×44px下限を測定した。OSキーボードの再現やアクセシビリティ全面適合の証明ではない。`prefers-reduced-motion` 時のアニメーション停止も確認した。

代表画面は [previews](./previews/) に保存。操作録画は30fpsのブラウザ記録で、抽出フレームも目視確認した。実機のフレームレートや60fps動作を保証するものではない。

## 操作の確認

- ワークスペースとターミナルの作成・切り替え、元の選択ペインへの復帰。
- 接続先／ペインごとの下書き・履歴・スクロール保持。
- `help`、`pwd`、`git status`、`clear` のサンプル応答。
- サンプルキーボードの大文字／記号切り替え、Ctrl、特殊キー、開閉。
- サーバー追加の空白・ポート番号検証、初回ホスト確認とキャンセル。
- テーマ変更、文字サイズ変更、シートの進む／戻る／Escapeとフォーカス。
- PCへの引き継ぎ、切断、再接続、接続中止、切断中の作成操作。
- 新規・空の接続先から作業を始める流れ。

日本語IMEについては、ブラウザのcompositionイベントを合成したEnter保護を確認する範囲に限定する。OSの実際の変換候補・確定入力や、ネイティブ端末のIME品質を検証したものではない。

## 最終の回帰確認

独立した機能レビューで発見した以下の問題を修正し、対象操作を再実行した。

- 初めて追加したサーバーの確認キャンセル時に、別の固定サーバー名と再試行先を出していた。対象のサーバーを保持し、案内と再確認先を一致させた。
- composition中の再描画で入力要素を置換すると、終了イベントが来ず入力不能になる可能性があった。古い変換状態を解除し、Enter誤送信防止の短いガードを保ちながら復帰する。
- コマンド履歴を呼び出した途中でペインを往復すると、退避していた下書きが復元されなかった。履歴カーソルと元の下書きを保持し、新しいコマンド送信／clearでリセットする。

最終の寸法・入力サイズ監査で対象の主要操作部品に44px未満の箇所はなく、HTML入力欄は16px以上。検証中のページ例外と外部HTTPリクエストは0件。`file://` で開いたHTMLでも、埋め込みフォント・画像の読み込みと `pwd` の操作を確認した。

独立した最終機能レビューの24項目が通過し、残存する重大な状態管理・操作の問題は見つからなかった。結合文字・家族絵文字の移動と削除、タブの単一選択と矢印キー操作、操作要素のアクセシブルネームも確認した。

シートはブラウザ標準の `<dialog>.showModal()` を使用する。ChromiumではTab循環の端で `activeElement` が一度BODYになり、次のTabでシート先頭へ戻る。アプリの処理を含まない最小のdialogでも同じ挙動を再現した。背面の操作要素へのフォーカス移動はなく、独自のフォーカストラップは追加していない。
