# 第4版のAppllama調査と設計判断

確認日: 2026-09-07

## 起点となった観察

ユーザーが支持した第3版のキャラクター・アイボリー・細罫線を保ち、日常操作を改善する。実ブラウザでワークスペースを10件に増やすと、名前で絞り込めず、設定タブから戻ると一覧のscrollTopが584から0へ戻る。ターミナルから別の作業へ移るときも、ホームで探し直す必要があった。

## 調査範囲

Appllamaで「workspace」「search」のキーワード検索と、落ち着いたノート／プロジェクト一覧の意味検索を行った。searchと意味検索はそれぞれ3ページを確認し、比較候補を抽出。さらにAgendaとUlyssesの関連フローを順番に取得した。

重複を除いた今回の静止画候補77枚をダウンロードし、10枚のコンタクトシートで実際に確認した。以前の調査で見た画面の再参照を含むため、過去の52枚へそのまま加算はしていない。Agendaの19画面とUlyssesの9画面を重点的に確認し、主参考3画面は大きい画像でも確認した。動画やget_screenが返した類似候補の未確認画像を、この77枚に含めていない。

作業用の画像とメタデータは `/tmp/meeterm-r4/references/`。画像・透かし・競合のブランドを成果物へ転用しない。一部の検索候補はメタデータのアプリ名と画像内容が一致しなかったため、主参考に採用していない。

## 第4版へ反映する判断

- 通常ホームの構成は保ち、一覧の近くに検索入口だけを加える。検索対象には「前回の続き」のワークスペースも含める。
- 検索中は入力欄と結果を主役にし、毎文字の入力で画面全体や入力要素を作り直さない。該当なし、クリア、閉じるを用意する。
- 検索語と一覧位置は接続先ごとに保ち、タブやターミナルから戻ったときに復元する。
- ターミナルのワークスペース名を選択ボタンにし、背後の作業を保ったシートで切り替える。選択中とterminal数を明示し、常設の二段タブは増やさない。
- 12件の作業を含むプレビュー状態を追加し、少数件だけでは分からない使い勝手も確認できるようにする。
- workspaceの代表パス表示は追加しない。パスはpaneによって異なるため、既存の名前とpane名を識別の手がかりとして残す。

本調査で観察したのは静止画の構造。参照アプリのスクロール位置保持・IME・アニメーションを実機で検証したという主張ではない。meeterm側の状態保持はHTMLの実操作で別途確認する。
